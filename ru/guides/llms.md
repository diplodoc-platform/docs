# Генерация llms.txt

##llms.txt## — это специальный текстовый файл в формате Markdown, который размещается в корне сайта и используется ИИ-системами для улучшенной навигации по страницам. Его главная задача — помочь правильно понять структуру и смысл сайта, выделить ключевую информацию и корректно её интерпретировать при генерации ответов.

##llms-full.txt## — это специальный текстовый файл в формате Markdown, который размещается в корне сайта и содержит полное текстовое содержимое всех страниц сайта для быстрого получения контента ИИ-системами.

В Diplodoc поддержана генерация файлов ##llms.txt## и ##llms-full.txt## для документации: необходимо добавить в `.yfm` параметр [##llms.enabled: true##](../settings.md#llms) или выполнить сборку с параметром `--llms`.

Структура собранного файла ##llms.txt##:

```markdown
# Название проекта

> Описание из llms.description

Дополнительные сведения из llms.details.

## Documentation

- [Заголовок статьи 1](ссылка-на-статью-1)
- [Заголовок статьи 2](ссылка-на-статью-2): содержимое поля description из метаданных статьи 2
- [Заголовок статьи 3](ссылка-на-статью-3): содержимое поля description из метаданных статьи 3
...

---

For more comprehensive documentation, see [llms-full.txt](llms-full.txt)
```

Особенности:

- для каждого ##toc.yaml## генерируется отдельная пара файлов ##llms.txt## / ##llms-full.txt##;
- поле `llms.description` из `toc.yaml` добавляется в качестве описания проекта; если оно не задано, используется значение из `.yfm`;
- поле `llms.details` добавляет Markdown-абзацы и списки после описания и перед разделом `## Documentation`; эти сведения не добавляются в ##llms-full.txt##;
- описание содержимого каждой статьи для ##llms.txt## берется из [поля ##description## в метаданных](../project/meta.md#description) страницы;
- в ##llms-full.txt## для уменьшения размера файла вырезаются теги `<style>` и `<script>` со всем их содержимым, а также не выполняется инлайнинг svg-изображений.

Текст ссылки на статью в ##llms.txt## выбирается из первого непустого значения в следующем порядке:

1. Поле `title` в [метаданных статьи](../project/meta.md) (`meta.title`). В Markdown-файле оно задаётся в начале файла между строками `---`.
2. Первый заголовок первого уровня (H1) в статье. Он определяется после подстановки переменных и раскрытия [включений](../syntax/includes.md), с учётом видимости содержимого для читателя. Для [разводящей страницы](../project/leading-page.md) используется поле `title` самой страницы.
3. Поле `name` соответствующего пункта [оглавления `toc.yaml`](../project/toc.md).

Значения, состоящие только из пробелов, пропускаются. Если ни одно из перечисленных значений не задано, используется `description` из метаданных статьи, а затем — путь из `href` пункта оглавления.

## Настройки для отдельного оглавления {#toc-metadata}

В `.yfm` задаются общие значения для всех оглавлений проекта:

```yaml
llms:
  enabled: true
  description: Документация продукта.
  details: |
    Начните с руководства по установке.

    - Примеры рассчитаны на последнюю версию продукта.
  url: https://example.com/llms.txt
```

В корне каждого [`toc.yaml`](../project/toc.md#structure) можно переопределить `description`, `details` и `url`. Например, в `ru/toc.yaml`:

```yaml
title: Документация на русском языке
llms:
  description: Руководства и справочник API на русском языке.
  details: |
    Прочитайте руководство перед обращением к справочнику API.
  url: https://example.com/ru/llms.txt
items:
  - name: Начало работы
    href: index.md
```

`description` — краткое описание в начале ##llms.txt##. `details` — дополнительные сведения в формате Markdown. Это произвольные абзацы и списки перед разделами со ссылками, а не отдельный раздел `## Optional`.

Поля применяются независимо друг от друга:

- Если поле отсутствует в `toc.yaml`, используется соответствующее значение из `.yfm`. Например, можно задать только русское описание, сохранив общие `details` и `url`.
- Пустая строка `description: ''` или `details: ''` убирает соответствующий текст, даже если в `.yfm` задано общее значение.
- Пустая строка `url: ''` отменяет общий URL. При включённой генерации страницы ссылаются на ##llms.txt## своего оглавления. При отключённой генерации ссылка не добавляется.

Для `url` укажите абсолютный URL или пустую строку. Все три поля принимают только строки. Включение генерации (`enabled`) и ограничение размера (`llmsFullMaxSize`) задаются только в `.yfm` или параметрах команды сборки.

Отдельное вложенное оглавление использует свои настройки и значения из `.yfm`, без наследования настроек родительского `toc.yaml`. Оглавление, подключённое через [вставку](../project/toc-includes.md), добавляет пункты в содержащее его оглавление, но не переопределяет его LLMS-настройки.

Ссылка `llms.url` выбирается по ближайшему оглавлению страницы. Она добавляется в Markdown-копию статьи и в статическую HTML-сборку как `rel="describedby"`. Поля `description` и `details` из `toc.yaml` также извлекаются для [перевода](../tools/docs/translate.md) как Markdown; URL не переводится.

При сборке с `--watch` изменения этих полей в `toc.yaml` применяются без перезапуска. Изменение описания или подробностей обновляет ##llms.txt##, а изменение URL обновляет ссылки затронутых страниц. После изменения `.yfm` сборку нужно перезапустить.

## Ограничение размера llms-full.txt {#llms-full-max-size}

Для проектов с множеством статей файл ##llms-full.txt## может получиться слишком большим для чтения ИИ-системами. Чтобы задать предельно допустимый размер создаваемого файла, можно указать ограничение в параметре [##llms.llmsFullMaxSize##](../settings.md#llms) в `.yfm`.

Обработка параметра работает следующим образом: если при добавлении в ##llms-full.txt## следующей статьи итоговый размер файла начинает превышать заданное ограничение, наполнение ##llms-full.txt## прекращается и отдается код сборки ##YFM022## (уровень **INFO**, можно [переопределить через yfmlint](../project/lint.md)).

## Подключение внешнего llms.txt {#external}

Если документация является частью сайта, у которого есть собственный файл ##llms.txt##, можно указать ссылку на него в параметре конфигурации `llms.url` для отображения в статьях документации:

```yaml
llms:
  url: https://example.com/llms.txt
```

Важно: для указания внешнего ##llms.txt## **не требуется** включать сборку ##llms.txt## в документации.

Ссылку можно [переопределить для отдельного оглавления](#toc-metadata) через `llms.url` в `toc.yaml`. Это переопределение также работает при отключённой генерации.
